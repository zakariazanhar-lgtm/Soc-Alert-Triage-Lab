# SOC Alert Triage Lab

A beginner SOC (Security Operations Center) project. I built a small lab on my own virtual machine, wrote two detection rules for Suricata, and investigated two simulated incidents with Suricata, Zeek and Wireshark.

> **Lab only.** All traffic was generated by me on my own machine. No third-party system was scanned or attacked, and no malware was used.

## What I did

**Case 1: Suspicious User-Agent.** I sent a web request with the fake header `User-Agent: BadBot-Test`. My Suricata rule raised an alert. I confirmed it in Zeek (logs of both requests) and in Wireshark (the header inside the packet). Verdict: true positive, but harmless, because I created the traffic myself.

**Case 2: Port scan.** I scanned my own machine with Nmap (ports 1 to 10000). My second rule raised one alert. Wireshark showed 10,000 connection attempts, and Zeek logged 10,000 connections (9,999 rejected and 1 answered by the open port). The rule stayed quiet on the normal traffic from Case 1.

## Files

- `SOC_Alert_Triage_Lab_Report.pdf`: the full report with screenshots: the Case 1 incident report, the Case 2 incident report, and the MITRE ATT&CK mapping (Case 1 maps to T1071.001 and Case 2 to T1046, both simulated)
- `Triage_Playbook.pdf`: a one-page checklist for handling alerts
- `rules/local.rules`: my two detection rules

## Detection rules

```
alert http any any -> any any (msg:"LOCAL BadBot User-Agent"; http.user_agent; content:"BadBot-Test"; classtype:trojan-activity; sid:1000001; rev:2;)
alert tcp any any -> any any (msg:"LOCAL Possible TCP port scan"; flags:S; threshold:type both, track by_src, count 20, seconds 5; classtype:attempted-recon; sid:1000002; rev:1;)
```

- Rule 1 alerts when a web request has the User-Agent `BadBot-Test`.
- Rule 2 alerts when one source sends 20 connection-opening packets (SYN) within 5 seconds.

## Tools

Suricata 8.0.7, Zeek (Docker), Wireshark, tcpdump and Nmap 7.95, on a Kali Linux virtual machine (MacBook Air M2).

## What I learned

- Check that the evidence contains what you expect before trusting "no alerts".
- A count of 0 only means something if the search text can match.
- Read the first error message. It usually points to the problem.

## Limitations

- Both cases are small, simulated lab tests, and the scan threshold has not been tuned on real traffic.
- The scan rule would miss a slow scan.
- The raw capture files are not included, because they contain private network details.
